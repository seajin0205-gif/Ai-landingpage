주요 UI, 왜 이렇게 배치했나

“예뻐서”가 아니라, 손과 시선의 이동을 줄이기 위한 사용성 결정입니다.

왜 Workspace 구조인가?

Chat·Image·Auto를 별도 앱처럼 두면 작업 상태가 툴마다 끊깁니다. 하나의 Workspace로 묶어야 Prompt·결과·히스토리가 같은 맥락에 남습니다.

Context continuity

왜 Prompt 입력창을 하단에?

대화형 AI 사용 습관과 같고, 결과를 본 뒤 바로 수정 Prompt를 칠 수 있습니다. 상단 고정은 결과 영역을 밀어내 반복 수정 루프를 끊습니다.

Thumb zone · Revise loop

왜 Preview를 오른쪽에?

LTR 읽기 흐름에서 입력(좌) → 판단(우)이 자연스럽습니다. 대화와 결과를 나란히 두면 Export 없이 Variant를 비교할 수 있습니다.

F-pattern · Compare

왜 History를 왼쪽(사이드)에?

이전 작업은 자주 쓰이지만 항상 펼쳐둘 필요는 없습니다. 좁은 사이드에 두면 메인 캔버스를 가리지 않으면서, 필요할 때 Prompt·결과를 바로 복원할 수 있습니다.

Progressive access

왜 Variant에 Card Layout인가?

리스트는 스크롤 비교가 느립니다. 동일 크기의 카드 그리드는 시선이 수평으로 이동해 A/B 차이를 더 빨리 판단하게 합니다.

Scanability

왜 Export를 결과 패널에 붙였나?

결정은 Preview를 본 직후에 이뤄집니다. 툴바에만 두면 시선·클릭이 다시 위로 갑니다. 결과 옆에 두면 “선택 → 내보내기”가 한 동작으로 끝납니다.

Proximity

돌아보며

AI UX에서는 기능보다 반복 수정 경험이 더 중요하다는 점을 배웠습니다. 생성만 잘 되는 것보다, 같은 맥락에서 고치고 비교하는 루프가 제품 가치를 결정합니다.

하나의 Workspace 안에서 작업 흐름을 유지하는 것이 사용자 경험을 크게 향상시킨다는 것을 확인했습니다. UI 통합은 '기능 합치기'가 아니라 '맥락 유지'가 목적입니다.

UI보다 사용자의 작업 흐름을 먼저 설계하는 것이 중요했습니다. Intent → Planning → Generation → Iteration → Export 순서가 모든 화면 구조의 기준이 되었습니다.

생성 이후의 수정 경험까지 고려해야 완성도 높은 AI 제품이 됩니다. Result Panel, Variant 비교, Export까지 한 화면에 두는 것이 핵심 설계 결정이었습니다.
